# MMORPG — Объектно-ориентированная игровая система (C++17)

Учебный проект по курсу **Объектно-ориентированного программирования (ООП)** на языке **C++17** с использованием системы сборки **CMake**.  
Проект представляет собой пошаговую тактическую MMORPG-систему с игровым полем, иерархией персонажей, игровой базой, ландшафтом с модификаторами характеристик, нейтральными объектами, системой команд с поддержкой отмены (`undo`), посредником взаимодействий и цепочкой обработчиков консольного ввода.

---

## Архитектура и реализованные паттерны проектирования

Проект построен по модульному принципу с разделением на заголовочные файлы (`include/`) и файлы реализации (`src/`):

### 1. Порождающие паттерны
* **Фабричный метод (Factory Method)** (`UnitFactory`, `CarryFactory`, `MidderFactory`, `SupportFactory`):
  * Персонажи сгруппированы по игровым ролям (`Carry`, `Midder`, `Support`), каждая роль имеет собственную фабрику, создающую конкретных героев.
  * Соблюдается принцип **OCP (Open/Closed Principle)**: добавление новой роли и новых персонажей не требует изменения кода игрового поля или посредника.
* **Прототип (Prototype)** (`Unit::clone()`):
  * Каждый конкретный юнит реализует виртуальный метод `clone()`, возвращающий `std::unique_ptr<Unit>`, что обеспечивает корректное глубокое копирование игрового поля `GameField`.

### 2. Структурные паттерны
* **Заместитель / Прокси (Proxy)** (`Terrain`, `TerrainProxy`, `TerrainMap`):
  * `TerrainProxy` оборачивает реальные клетки местности (`Plains`, `Forest`, `Swamp`, `Mountains`), контролирует доступ (блокирует вход на непроходимые горы `Mountains`), ведёт логирование перемещений и управляет применением/снятием эффектов ландшафта (`onEnter` / `onLeave`).
* **Фасад (Facade)** (`GameFacade`):
  * Предоставляет единый высокоуровневый интерфейс для управления игрой (`createUnit`, `moveUnit`, `attackUnit`, `buildBuilding`, `research`, `undoLastCommand` и др.), скрывая сложную координацию команд, истории выполнения и игрового посредника.

### 3. Поведенческие паттерны
* **Наблюдатель (Observer)** (`IObserver`, `IObservable`, `UnitEvent`, `Base`):
  * Класс `Unit` наследует `IObservable` и рассылает события `UnitEvent` (`Created`, `Damaged`, `Destroyed`).
  * Игровая база `Base` реализует `IObserver`: отслеживает состояние созданных бойцов и при их гибели автоматически освобождает слот активного юнита.
* **Стратегия (Strategy)** (`IInteractionStrategy`, `PowerBoostStrategy`, `TrapDebuffStrategy`, `FullHealStrategy`, `TeleportStrategy`):
  * Поведение нейтральных объектов (`NeutralObject`) инкапсулировано в сменные стратегии взаимодействия с юнитом, что позволяет гибко изменять логику объектов во время выполнения.
* **Посредник (Mediator)** (`GameMediator`):
  * Централизует взаимодействие между игровым полем (`GameField`), картой ландшафта (`TerrainMap`), игровой базой (`Base`), постройками (`Building`), фабриками юнитов и нейтральными объектами, устраняя дублирование логики и прямые зависимости между подсистемами.
* **Команда (Command)** (`ICommand` и 10 конкретных команд):
  * Инкапсулирует каждое игровое действие (`CreateUnitCommand`, `MoveUnitCommand`, `AttackUnitCommand`, `CollectResourceCommand`, `HealCommand`, `BuildCommand`, `ResearchCommand`, `DistributeResourcesCommand`, `ProduceUnitCommand`, `StatsCommand`) в отдельный объект с методами `execute()`, `undo()` и `getName()`, что позволяет вести журнал действий и выполнять откат (`undo`).
* **Цепочка обязанностей (Chain of Responsibility)** (`Handler` и 10 обработчиков в `Handlers/`):
  * Разгружает `GameFacade` от разбора текстового ввода: запрос последовательно проходит по цепочке (`CreateHandler` → `MoveHandler` → `AttackHandler` → `CollectHandler` → `HealHandler` → `BuildHandler` → `ResearchHandler` → `ProduceHandler` → `StatsHandler` → `HelpHandler`), пока профильный обработчик не распознает команду и не передаст её в фасад.

## Игровые сущности и механики

### Атрибуты (`include/Attributes/`)
* **`Health`** — текущее и максимальное здоровье с валидацией урона и лечения (`decrease`, `increase`, `isZero`).
* **`Armor`** — показатель брони, снижающий входящий урон (`reduceDamage`, `modifyValue`).
* **`Attack`** — показатель атаки и расчёт итогового урона по цели (`calculateDamage`, `modifyDamage`).

### Иерархия персонажей (`include/Units/`)
Трёхуровневая иерархия наследования (`Unit` → Роль → Конкретный герой):
* **Carry**: `PhantomAssassin` (`P`), `Lifestealer` (`L`)
* **Midder**: `Invoker` (`I`), `ArcWarden` (`A`)
* **Support**: `Dazzle` (`D`), `WitchDoctor` (`W`)

### Ландшафт (`include/Terrain/`)
| Тип местности | Символ | Проходимость | Эффекты для ролей |
| :--- | :---: | :---: | :--- |
| **Равнина (`Plains`)** | `.` | Да | `Carry`: **+10** к атаке |
| **Лес (`Forest`)** | `T` | Да | `Midder`: **+10** к атаке; `Support`: **-5** к броне |
| **Болото (`Swamp`)** | `~` | Да | `Carry` и `Midder`: **-5** к броне; `Support`: **+8** к броне |
| **Горы (`Mountains`)** | `^` | **Нет** | Непроходимы для всех юнитов |

### Нейтральные объекты и перегрузка операторов (`include/NeutralObjects/`)
* **`PowerRune`** (`*`) — одноразовая руна силы (**+15%** к атаке).
* **`Trap`** (`x`) — одноразовая ловушка (**-5%** к броне и **-5%** к атаке).
* **`HealingFountain`** (`+`) — источник лечения (восстанавливает **100% HP**).
* **`Teleport`** (`@`) — зеркально телепортирует юнита относительно центра карты с проверкой проходимости и занятости целевой клетки.
* **Перегруженные операторы**:
  * `unit + neutralObj` — активирует взаимодействие юнита с нейтральным объектом.
  * `!neutralObj` — проверяет, деактивирован (израсходован) ли объект.

### Контейнер поля и управление памятью (`include/Field/`)
* **`GameField`** — управляет юнитами через `std::unique_ptr<Unit>`, реализует **Rule of Five** (глубокое копирование через идиому *Copy-and-Swap* с `clone()` и `noexcept` семантику перемещения).
* **`GameFieldIterator`** — собственный STL-совместимый итератор с автоматическим пропуском пустых ячеек (`skipEmpty()`).

## Консольные команды (Interactive Mode)

После демонстрационного сценария программа переходит в интерактивный режим, поддерживающий следующие команды:

* `create <unitType> at <x>,<y>` — нанять юнита (`PhantomAssassin`, `Lifestealer`, `Invoker`, `ArcWarden`, `Dazzle`, `WitchDoctor`)
* `move unit <id> to <x>,<y>` — переместить юнита по ID
* `attack unit <attackerId> -> <targetId>` — атаковать вражеского юнита
* `collect resource <resId> by unit <unitId>` — собрать ресурс в пользу базы
* `heal unit <targetId> by <healerId>` — вылечить союзного юнита
* `build <buildingType> at <x>,<y>` — построить здание (`barracks`, `tower` и др.)
* `research <techId>` — изучить улучшение на базе (например, `attack_upgrade`)
* `distribute <amount> <resType> to <targetBuilding>` — распределить ресурсы со склада базы
* `produce <unitType> in <buildingId>` — произвести юнита в здании
* `stats [units|buildings|resources]` — вывести статистику мира
* `undo` — отменить последнюю обратимую команду
* `history` — показать журнал выполненных команд
* `map` — отрисовать карту мира `15x15`
* `help` / `exit` — справка по командам и выход из программы

## Сборка и запуск

Требования: компилятор с поддержкой **C++17** и **CMake >= 3.15**.

```zsh
cmake -B build
cmake --build build
./build/game
```
